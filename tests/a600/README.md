# A600AirPrint – test report

## 1. Clean emulator, public ADF (17-10-2026)

**Environment.**
- Amiberry 8.3.0 with `chipset_compatible=A600` and a cycle-exact 68000 at 7 MHz.
- 2 MB chip + 4 MB fast RAM, Kickstart 40.63 and Workbench 40.42; printer.device 39.6.
- A **fresh copy** of the Workbench 3.1 test disk, with the old AirPrint files from earlier experiments removed (`airprint.device`, `Printers/AirPrint`, `AirPrint.prefs`).
- A new, empty `Work:` holding only the A600 network package (AmiTCP 3.0b2 + plipbox.device 0.6 + smbfs).
- `plip0` was UP. For the test only, an emulated network card carried the traffic to the fake printer and to Samba.

**Disk.** `A600AirPrint-public.adf`, built with `build_public.py` and a test configuration (printer = the fake printer). The test does **not** use any later prefs override: the address comes only from the build configuration.

**Test deviations, reported honestly:**
- The GUI step *Prefs/Printer → AirPrint, Serial, Save* was replaced by copying a `printer.prefs` that had earlier been saved in that GUI. The GUI step itself was proven in an earlier emulator round and on the real A600.
- During the first colour page, a test keystroke went into the wrong window. A half-typed line in the console held back the script's last message until it was completed. The print job itself was not affected; it was identical. The during-print checks were therefore repeated with a second colour page and a delayed background script (P5b).
- The log of an unintended check run *after* the first colour page was overwritten by a test helper. Its content (SER free, Retro: OK) was seen in the session and matches P6.
